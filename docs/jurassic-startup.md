# Jurassic Park 2015: native startup investigation

**Desktop controls now reach scored gameplay.** Verified on the user's NVIDIA RTX 3050 display using the Rust-prepared desktop profile, without GDB or a timeout: Start opens mission selection, mouse aim produces a visible reticle, and held fire produces shots and a score of 75. Full-game stability, physical cabinet devices, player-two aiming and Jurassic audio remain unfinished.

## Open on the desktop

```sh
cargo build -p arcade-linux-shim --target i686-unknown-linux-gnu
cargo run -p arcade-desktop -- --launch-jurassic games
```

The workbench also has **Open Jurassic Park on my display**. Startup may show a black loading window for roughly 15 seconds before the attract video. The game opens in a 1360×768 window; **Esc** or closing the window exits. The session remains open until exited. Main audio currently uses SDL's dummy backend; cabinet/rumble audio is not implemented.

Desktop controls (click/focus the game window first):

| Input | Action |
| --- | --- |
| 1 / 2 | Player-one / player-two Start |
| Mouse | Player-one aim |
| Left mouse | Fire / shoot a selection; hold for automatic fire |
| Right mouse | Secondary gun trigger (action not yet verified) |
| 5 / 6 | Coin channels one / two (current copied settings are free play) |
| T / 9 | Test / service |
| Up / Down / Enter / Backspace | Menu up / down / select / cancel |
| Esc | Exit |

Only player one has mouse aiming. The red **RIO Disconnected** overlay is suppressed in desktop mode by routing the banner renderer's fingerprint-checked error-flag reads to a display-only copy with the RIO bit masked. The shim logs that physical RIO is unavailable; connection status and reconnect behavior remain unchanged. These are desktop input maps, not a complete RIO hardware emulator. Original SDL input processing supplies press/release/held states. The Rust shim validates the input ABI and orders desktop maps after cabinet maps on each SDL poll, including after the game rebuilds its mappings. Physical-gun smoothing is disabled for absolute mouse coordinates; it otherwise blends with absent cabinet samples. No input events are automatically generated by the launcher.

The core checks the exact supplied executable hash, clears nine stale import metadata values, and writes a separate `game-desktop` snapshot. The desktop profile omits unavailable cabinet security initialization and uses the supplied plaintext script backups rather than calling their decryption path. All 1,516 backup scripts must carry the expected plaintext marker before execution is permitted. This does not implement a HASP device or its cryptography. The unadapted original/native diagnostic modes below still stop at their recorded security checks.

The black screen was resolved with `SDL12COMPAT_OPENGL_SCALING=0`. The current SDL 1.2 compatibility library's scaling/presentation path conflicted with the game's direct OpenGL framebuffer handling. A trusted 32-bit SDL color test proved the same sandbox, GPU and shim could present correctly; framebuffer readback also contained actual game pixels before this fix. [SDL's configuration documentation](https://github.com/libsdl-org/sdl12-compat#configuration-options) describes this scaling option and its black-screen workaround. The shim also forces windowed video mode, so disabling scaling does not permit the game to change the desktop resolution.

The launcher mounts the selected X11 socket/auth file and available GPU nodes, keeps game/system assets read-only, and uses copied saves under `runtime/jurassic/desktop/`. Cabinet `nvidia-settings` commands are replaced by an inert private command. The `/pmuser` alias fixes the supplied save symlink. The shader108 output fixes are staged in runtime-only copies. The verified desktop image SHA256 is `9fd96c7e1d14c8863c1e790545c21e9d81f6f72a6b8cb16686f25da0fac313bc`. The Python/shell harness only prepares the sandbox and process; the image compatibility changes and guest shim are Rust. No existing arcade loader is used.

## Earlier startup investigation

The following diagnostics preserve comparison with the original and unadapted supplied snapshot. Their results are separate from the working desktop startup profile.

No TeknoParrot binary, profile or launcher is executed. All original game files remain unchanged. Big Buck Hunter's working launch path remains separate.

## Reproduce

Stage dependencies locally (already done on this machine):

```sh
./scripts/setup-jurassic-libs.sh
```

The script extracts NVIDIA's original PhysX 2.8.1 Linux libraries and Arch's archived 32-bit Theora library under `runtime/jurassic/libs/`. It checks pinned SHA256 hashes and does not install system packages. Existing host 32-bit glibc, SDL 1.2 compatibility, GL/GLU/GLUT, udev, X11 and C++ libraries are also used.

Original protected build:

```sh
cargo run -p arcade-desktop -- --probe-jurassic games
```

Supplied modified snapshot, without repairs:

```sh
cargo run -p arcade-desktop -- --probe-jurassic-legacy games
```

Experimental native import repair:

```sh
cargo build -p arcade-linux-shim --target i686-unknown-linux-gnu
cargo run -p arcade-desktop -- --probe-jurassic-native games
```

These commands currently return errors deliberately: none has demonstrated a working game. They save JSON results, a syscall trace and a runner log in `runtime/jurassic/`, prefixed `original-`, `legacy-` or `native-`. The workbench also has **Diagnose repaired Jurassic Park startup** for the native-repair check. It does not display a stale Big Buck Hunter screenshot as a Jurassic result.

Each run validates the exact source SHA256 and creates a separate runtime snapshot. It executes inside Bubblewrap with read-only game assets/system libraries, private `/tmp`, fresh `/dev` and `/proc`, no desktop display, no host home directory and a private network namespace. A 10-second timeout bounds startup. No cabinet boot/service scripts are run.

## Build identity and findings

| Input | SHA256 | Native result |
| --- | --- | --- |
| `game_original` | `6bb8a70dc0ee3f9d7ac3672d7dc8cf4aadec44b0f96c050ace96a7633d26af11` | exits 1 before engine startup |
| `game_legacy_patched` | `c18a9329e72a363937155d245440694e58b5a1e27984016ae7648af3413b4269` | SIGSEGV during initialization |

The original is ELF32/i386 with entry `0x0904a8da`. Its imports include `libtheora.so.0`, `libPhysXLoader.so.1`, SDL 1.2 and OpenGL. Its native trace now resolves those libraries, then attempts three TCP connections to `127.0.0.1:1947`; each returns ECONNREFUSED and the process exits. The file exports HASP/Dongle functions and carries a protected startup layer. This result does not establish that installing a service alone would suffice; a valid licence/device or a reconstructed executable/runtime would still need validation. The user has only the supplied files.

The supplied modified image has a normal CRT entry at `0x0813befc`, but retains stale runtime addresses. Initial GDB failure jumped to unmapped `0xb7227dc0`. `LD_BIND_NOW=1` moves it past that lazy-binding failure, then X11 initialization hits a second stale pointer. Nine undefined dynamic symbols also have nonzero saved values: strcmp, malloc, fprintf, the C++ ios-base destructor/personality/pure-virtual symbols, free, pthread_cancel and realloc. Clearing those values in a copy advances initialization further.

Our native mode clears exactly those nine values, enables eager symbol binding, and rebinds **474 fingerprint-verified imports** plus **thirteen caller-identified bindings/adapters** (libc 218, pthread 54, libm 37, SDL 42, core OpenGL 123). The archived Ubuntu i386 glibc 2.19-0ubuntu6.6 reference matches four independent libc import anchors and eight pthread anchors at consistent saved load bases. Matching debug symbols identify optimized string/memory implementations by their public IFUNC APIs. The reference libraries are parsed as data; they are never loaded into the game. Execution uses the current host libraries.

`crates/arcade-core/src/bin/recover-jurassic-imports.rs` generates the binding tables. It requires the exact supplied snapshot hash, rejects inconsistent or ambiguous reference-library fingerprints, and checks the debug library's GNU build ID. The shim validates all PLT instruction/slot identities and resolves all replacement symbols before writing any slot. A preflight error terminates startup. Repairs affect the runtime copy and its process memory; source game files stay unchanged. This remains a build-specific compatibility repair, not a general ELF loader or a complete reconstruction of every external import.

The repaired run completes initial constructors and reaches game initialization. The runner log reports:

```text
[jurassic] rebound 474 fingerprint-verified imports and 13 supplemental imports
Assert file src/game_sys.c, line 760:
Game dongle initialization failed!
```

The process exits with status 0 despite that assertion, so exit status alone cannot indicate successful startup. The JSON result records `game_dongle_initialization_failed: true`. The trace also records refused localhost:1947 connections. The game-level assertion takes precedence over the generic service-connection diagnosis. Separate `game-original`, `game-legacy`, and `game-native` snapshots prevent one diagnostic mode overwriting another's image.

The supplied cabinet command uses `-n`, but this image's command-line dispatch does not implement that option; it does not provide a route past dongle initialization. The separate debugger experiment below investigates the next graphics/resource stages. PhysX operation, cabinet I/O, motion and gun input remain unverified. The supplied files alone have not yet established a usable licence/device path. The game-level initializer returned 2 with embedded HASP status 14 in GDB; no functioning service/key was demonstrated.

### Graphics/resource exploration (explicit debugger skips)

```sh
python3 scripts/jurassic-explore.py
# Shorter check:
python3 scripts/jurassic-explore.py --seconds 10
```

This is a bounded development experiment, not a playable launch mode. It requires GDB, Bubblewrap, the prepared native image/shim/libraries, the existing private Xvfb tool, ImageMagick and xdotool. It runs for up to 75 seconds and captures private-display frames at 10-second intervals. Its GDB commands deliberately skip `GameInitDongle`; normal native mode does not. It also redirects `SysLog` to printf and enables verbose shader error logging in process memory.

The active script folder contains 1,162 plaintext scripts and 354 still-encrypted scripts. All 1,516 have plaintext `//\n`-marked backups under `programs_dec`. The experiment validates that coverage, mounts the backups read-only over the script directory, and conditionally avoids the script decryption branch only when the loaded buffer begins with that exact marker. An earlier run without the backups looped retrying `DongleDecrypt` on a missing handle. This does not implement cryptography or a valid cabinet dongle.

The supplied `g5/dino/pmuser` symlink resolves to `/pmuser` in the guest; both `/pm/pmuser` and `/pmuser` are bound to the private save copy. Adjustment/audit saves now work. The private environment has copied writable saves and an inert private USB automount-rule file; the original code otherwise attempts to create rules under `/etc`. Host system configuration is not mounted writable. Main SDL audio uses the dummy backend. The separate JPS cabinet/rumble audio device is still unavailable.

Current exploratory evidence: an X window named **Jurassic Park Arcade** exists, and GDB reaches `SDL_GL_SwapBuffers`. All captured frames through 60 seconds are black. The main thread waits in Mesa's rendering queue while llvmpipe worker threads execute rendering code. The initial four shader108 failures were traced to mixed legacy `gl_FragData` and named `out_Bloom` outputs. The experiment now stages six runtime-only shader overrides (five shader108 fragment variants and the shared bloom include), using named outputs consistently. Subsequent runs compile these shaders without those errors. The source shader files remain unchanged. Cabinet I/O/rumble initialization also reports missing hardware. A window title and a swap call do not establish visible rendering or gameplay.

Results are written under `runtime/jurassic/exploration/` (`gdb.log`, `windows.txt`, `screen-*.png`, `result.json`). The structured result explicitly records the debugger skips and `gameplay_verified: false`. No host desktop display is attached by this experimental script. The next rendering investigation must resolve the black frame before offering a normal desktop launch. Mesa API diagnostics currently report invalid draw-buffer/attachment state; these errors are evidence to investigate, not proof of the black frame's cause. Direct window capture also remains black. The mapped window is 1024×768. After the shader/GLX fixes, short runs reach GLCGZ movie frame decoding and rendering without a segmentation fault.

### Additional import fingerprints

Math uses matching glibc/libm debug symbols and three independently identified VecInit calls (sinf, cosf, tanf). SDL uses Ubuntu 1.2.15-8ubuntu1.1: four startup/video anchors reject the adjacent -8ubuntu1 build, whose later video offsets differ by 16 bytes.

Core OpenGL uses a matching dispatch layout from NVIDIA 340.76 as reference data. Thirteen anchors cover both fixed-function calls and GLSL calls. These do **not** establish that the original cabinet used that exact driver version. Vendor/extension layouts differ across versions; the generator excludes ARB/EXT/NV/etc. exports. The three extension calls used here are identified from their callers instead: `printInfoLog` needs `glGetObjectParameterivARB`/`glGetInfoLogARB`, and `ResImg1Upload` needs `glGenerateMipmapEXT`. A modern NVIDIA reference passes the older fixed-function anchors but fails the added GLSL anchors and is rejected. No archived driver or installer is executed.

The supplemental GLX bindings also restore `glXGetProcAddressARB`, `glXQueryVersion` and `glXGetClientString`, identified from the embedded extension loader's arguments/callers. Their stale addresses were reached when the movie subsystem initialized.

VSync now uses SDL's `SDL_GL_SWAP_CONTROL` instead of sending a vendor GLX swap-interval request before a context exists. A trial with direct vendor GLX control produced `GLXBadContextTag`; the SDL adapter advances past that failure. Rendering still needs investigation.

### Reproduce import recovery

The matching reference files currently reside under ignored `runtime/tools/jurassic/`. After extracting the Ubuntu reference and matching debug packages, regenerate libc bindings with:

```sh
cargo run -p arcade-core --bin recover-jurassic-imports -- \
  'games/linux based/Jurassic Park 2015/game_legacy_patched' \
  runtime/tools/jurassic/libc-2.19-0ubuntu6.6/lib/i386-linux-gnu/libc-2.19.so \
  crates/arcade-linux-shim/src/jurassic_libc_bindings.rs \
  runtime/tools/jurassic/libc-debug-2.19-0ubuntu6.6/usr/lib/debug/lib/i386-linux-gnu/libc-2.19.so
```

For pthread, use `libpthread-2.19.so` from the same reference directory, output `jurassic_pthread_bindings.rs`, and omit the debug argument. The generated tables are checked in as source; normal builds do not need the archived reference files.

The folder also contains game-engine headers and decrypted-looking script assets. Those help identify interfaces; their presence does not prove the executable or all assets are already usable without their original runtime.
